# LLMっぽい画面の特徴と対処

調査日: 2026-10-19。特定のアプリの評価から離れ、生成UIについての解説と、従来のUI設計・文章設計の原則を調べた。

「LLMっぽさ」は統一された学術的な判定基準ではない。以下は繰り返し指摘される傾向と、それに対する設計判断。フォントや色だけで生成物を判定するものではない。

| 兆候 | 困る理由 | 対処 |
| --- | --- | --- |
| 紫のグラデーション、ガラス、光彩を用途に関係なく使う | 製品固有の目的が見えず、どれも同じ印象になる | 作業と対象ユーザーを先に定め、色・書体・密度を理由付きで選ぶ |
| 同じカード、丸いバッジ、枠で全項目を囲む | 重要なものと補足が同じ強さになる | 比較するデータは行や列で揃える。区切りは余白と細線を優先 |
| 常設の「Connected」「Ready」や装飾的な緑ドット | 次の操作に影響しない情報が注意を奪う | 待機時間、失敗、操作の結果など、その時に必要な情報を表示する |
| 便利そうな機能をすべて初期画面に出す | 本来の作業が選択肢に埋まる | 頻繁な作業を直接操作できる位置に置き、まれな設定は一段だけ開いて出す |
| 大げさな宣伝文、曖昧な見出し、説明の繰り返し | 何をする操作か伝わらない | 対象と動作を具体的に書く。「体験を向上」ではなく「パスをコピー」 |
| 常時アニメーション、ホバーごとの動きや通知 | 操作中の視線や集中を乱す | 状態変化を伝える動きだけにし、バックグラウンド処理は成功通知を出さない |
| 見た目だけを直し、次の実装で元に戻る | 判断が共有されずテンプレートが増える | 設計方針を保存し、実データの長文・空・失敗・狭い幅で見直す |

対処は「装飾を全部禁止する」「別の流行フォントに変える」だけでは足りない。日本語の制作ツールなら、読みやすいOSの書体や密度のある一覧に理由がある。情報を削りすぎて、進行状況・操作結果・利用条件まで見えなくするのも避ける。

## 根拠と読み分け

- [Anthropic: Improving frontend design through Skills](https://claude.com/resources/articles/improving-frontend-design-through-skills) — 生成時の定型への収束と、用途・視覚方針を具体的に指定する方法。生成ツール提供者による解説であり、特定の書体を普遍的に禁止する根拠にはしない。
- [NN/g: Aesthetic and Minimalist Design](https://www.nngroup.com/articles/aesthetic-minimalist-design/) — 不要な情報は必要な情報と注意を奪い合う。必要な操作を維持したままノイズを減らす。
- [NN/g: Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/) — よく使う機能を初期表示し、専門的・まれな機能は求めたときに示す。隠す操作への入口は明確にする。
- [NN/g: UI Copy](https://www.nngroup.com/articles/ui-copy/) — 操作名は具体的で短く、曖昧な一般語や過剰な説明を避ける。
- [GOV.UK: Notification banner](https://design-system.service.gov.uk/components/notification-banner/) — 通知は重要な情報や操作結果に使い、メインのタスクを妨げない形を選ぶ。
- [SmoothUI: AI Design Slop](https://smoothui.dev/blog/ai-design-slop) — 同型のカード・グラデーションなどの現場での指摘と、生成後に見直して直す手順。製品宣伝を含むため、一般原則の裏付けには上の一次資料を使う。

## 今回の反映

- サイト単位の色ドットと件数、重複する凡例を撤去。素材ごとのライセンス色・アイコン・規約リンクは維持。
- キーボード説明は設定内へ。速度・ピッチは「速度・ピッチ」から開き、外側クリックかEscapeで閉じる。
- キーなしでも使えるFreesoundのAPI設定は折りたたむ。
- 詳細のタイトルと同じ説明、種類だけの説明、追加済みの装飾的チェックを撤去。原本か試聴用かは短く明記。
- ホバー中の先読み失敗は通知しない。明示的な再生・保存での失敗と検索失敗は引き続き表示。
- `Connected` のような常設表示は元から存在しないため、新たな代替表示も追加しない。

検索、保存、パスのコピー、比較、プロジェクト、ライセンス確認は要求された作業なので削除しない。使用頻度の裏付けがない機能を、見た目の印象だけで不要と断定しない。
