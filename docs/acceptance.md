## 直近の画面変更後の確認

`npm run test:ui`はheadless Chromiumで実rendererを動かす。API・音声・保存先はfixtureで、実サイトやOS連携の再検証には数えない。以下を確認済み。

- 速度・ピッチの開閉、Escape・外側クリックで閉じる操作、値の反映。
- 折りたたんだAPI設定とキーボード説明へのアクセス。
- 上下キーの選択、4件の比較、ブラインド表示、クレジット不要フィルタ。
- ホバー先読みの失敗で通知しないことと、保存ボタンのIPC呼び出し。
- 320 / 520 / 760 / 920 / 1360pxで横に溢れず、調整パネルも収まること。
- お気に入り・履歴・使用素材の検索語とサイト絞り込み。日本語「雨」と全角英語「ｒａｉｎ」で保存済みのRainfallを表示し、Trainを除外。
- 保存済みの一覧では検索対象サイトを空で渡し、各サイトの検索を始めないこと。全音源へ戻るとサイト横断検索を再開すること。
- 再生履歴が登録順ではなく直近の再生順になること。

最新のコードでは画面を表示する検証を再開していない。以前の実機結果を今回の変更後の実機結果として扱わない。

Mac Universal版の生成物は`dist/mac-universal/AllsAmple.app`。`node scripts/verify-mac-universal.cjs`で実行ファイルとElectron Frameworkのarm64/x86_64両スライス、全srcファイルとASARのバイト一致、SampleTap本体と14テストの無改変、`codesign --verify --deep --strict`の成功を確認した。これはad-hoc署名の整合性であり、Developer ID署名・公証・Intel実機での起動を証明しない。この検証コマンドは標準ではアプリを起動しない。`--with-runtime`は表示を伴うため、利用者が求めた場合だけ実行する。
