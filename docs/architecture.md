# 構成

- `src/main/providers/`: サイトごとに`id`、`name`、`catalog`、`restore()`、非同期ジェネレータ`search(query, { signal })`を持つ。独立したネットワークキューと例外境界で並列実行。
- `src/main/network.cjs`: 取得先ホストの限定、時間制限、サイズ上限、120msのアクセス開始間隔（音声の操作要求はこの待機を入れない）。robots.txtは読まない。
- `src/main/library.cjs`: 音源の取得共有、原バイト列のキャッシュ、重複名を壊さない書き出し。
- `src/main/index.cjs`: ウィンドウ、IPC送信元検証、限定したアプリ内プロトコル、OSのファイル・クリップボード操作。
- `src/main/preload.cjs`: 操作ごとの最小限のブリッジ。汎用IPCやNode APIは公開しない。
- `src/renderer/`: フレームワーク・ビルドなしのUI。Electron APIとの接点は`window.allsample`だけ。将来のパネル版ではこのブリッジを差し替える。
- `src/main/automation/`: PlaywrightからElectron内のChromiumを操作。非表示ウィンドウはNodeなし・sandboxあり。127.0.0.1の一時CDPポートに接続し、別のブラウザ実体は同梱しない。
- `src/main/providers/browser-catalog.cjs`: 4サイト共通のページ操作・行ID・検索URL・プレビューの権利表示。URL解決は無改変hookへ委譲する。
- `vendor/sampletap/`: MIT由来の中核とテストを無改変で保管。Chrome拡張の保存APIや挿入ボタンは流用しない。

効果音ラボは公開HTMLに配布リンクが揃っているので、非表示ウィンドウを作らずHTMLを解析する。動的サイト用のページ文脈とは配管を分け、静的サイトの不要な描画コストを避ける。

## データの意味

`commercial`等は`true / false / null`。`null`は条件付き・不明であり、許可扱いにしない。緑バッジは無制限の利用許可を意味しない。On-Jinの表記・営利条件など、個別の留意事項は`license.note`で表示する。

`isPreview: false`はページの配布リンクから取得する素材、`true`は試聴専用。形式は実際にページ上で確認できたリンクから決め、拡張子の置換で高品質版を捏造しない。

## 保存

ElectronのuserData内に索引・音声を保存。音声は`.part`からrenameする。ネイティブドラッグはユーザー操作内で同期的に開始する必要があるため、ホバー/クリックで先に音源をキャッシュする。未取得なら後から勝手にドラッグを開始しない。

## 現在の制約

魔王魂の検索は1検索あたり最大5ページ。効果音ラボ・On-Jinは初回の検索で公開カテゴリを順次索引化し、途中結果を表示する。サイトの途中失敗時は取得済み結果を残す。動的4サイトは先頭から最大3回のスクロールで結果を収集する。署名付きURLは保存時に行から再解決し、必要ならページを再読込する。音声キャッシュは初期上限2GiBで、使用中の音源を除いて最終アクセスの古い順に整理する。

## 読み込みの優先度

`priority-queue.cjs`でユーザー操作を先読み・後続検索より優先する。AudioCacheは同時3件のうち先読みを1件に制限する。同じ音源の先読み中に再生・保存要求が入った場合は、重複取得せず待機中の要求を昇格する。ブラウザ検索は1検索全体でロックせず、結果バッチごとにキューへ戻す。非表示ページでは画像・フォントを取得せず、必要なDOM・スクリプト・音声とChromiumの応答キャッシュを使う。

再生は音声の取得後に開始し、波形のデコード完了を待たない。ホバーでは先読みだけを行い、再生しない。上下矢印で選択し、再生中は次の音へ切り替える。停止中は無音の選択と先読みを行う。リストの波形は可変幅で、狭い画面でも削除せず下段へ配置する。

## ライブラリと比較

`library-ui.js`は比較トレイ・フォルダ管理・プロジェクトのUIを担当する。素材IDとメタデータをmainの`library-index.json`、プロジェクト・使用ID・比較ID・お気に入り等を`ui-state.json`へ保存し、起動時に合わせて復元する。`JsonStore`は書き込み順を保ち、一時ファイルからrenameする。旧localStorageの記録は初回に引き継ぐ。

ローカルフォルダは`local-index.json`で登録を維持し、更新時刻・サイズが同じファイルの解析を再利用する。音声はキャッシュへコピーせず登録元を読み、読み出し時に実パスと登録ルートを照合する。フォルダ登録を解除しても元ファイルは触らず、過去のプロジェクトの素材名・クレジット情報は残す。未登録の音源は試聴できないことを明示する。

比較候補は最大4つ。ブラインド中は結果も候補に限定し、名前をA〜Dへ置き換える。サイト一覧・ライセンス・説明・保存先など出典が見える領域を隠し、プレイヤーと詳細にも同じ匿名表示を使う。320pxでは候補を2列にし、下部プレイヤーと重ならない高さを確保する。

## フィルタと試聴の変調

`filters.js`はUIから独立した判定関数。許可の不明値はtrueへ変換しない。長さ/BPM等の条件を有効にすると、その情報がない素材は一致から外す。キーは異名同音を正規化し、長短調は分ける。`filter-controls.js`が入力と用途別プロファイルを接続する。試聴から得た情報は検証付きIPCでmainへ渡す。ローカル素材は既存の実ファイル情報、オンライン素材はキャッシュ音声のヘッダを使って長さ・チャンネル・サンプルレートを確定し、索引へ記録して次の検索へ引き継ぐ。decodeAudioDataは出力デバイスのレートへリサンプルするため、そのレートを元ファイルの値として保存しない。

`audio-graph.js`は同じHTMLAudioElementをWeb Audioへ接続する。SoundTouchJSの上流モジュールとAudioWorkletをアプリ内プロトコルから配信し、依存先のコードは改変しない。音源のplaybackRateとSoundTouchNodeのplaybackRateを揃えて速度を変え、ピッチはpitchSemitonesで独立させる。波形のデコード完了は再生条件にしない。

停止は出力Gainを即座に0へ落とし、バッファが無音になってからAudioContextを休止する。再開・頭出し・候補切替では処理ノードを作り直し、前の音のバッファを流さない。世代番号で遅れて完了した前の再生要求を破棄する。再生調整は保存・キャッシュの音声には書き込まない。

## 音声キャッシュの容量管理

`cache-policy.cjs`は音声ディレクトリのアプリ所有ファイルだけを対象にする。上限は`cache-settings.json`へ保存する。最終アクセス時刻をファイルのmtimeへ反映するため、再起動後も順序を維持できる。ホバー直後の音は15秒間保持し、比較候補・選択中・プレイヤーの音源はIDで保護する。保護解除時や取得完了時に容量整理を予約する。保護中は上限を一時的に超えることを許す。

コピー・ヘッダ解析は`AudioCache.acquire()`、アプリ内プロトコルは`AudioCache.response()`で参照を保持する。プロトコルは読み出しの完了時に解放し、キャンセル・無効なRange・転送エラーでも参照を残さない。削除と読み出しの競合はIDごとに調停し、別のファイルの整理完了を音声が待つことはない。メタデータ走査は32件ずつに分ける。

削除通知でrendererの音声取得済み情報だけを無効にする。波形・ライセンス・使用素材の情報は残し、次のホバーから再び音声を先読みできる。書き出し先のファイルや登録フォルダの原本は走査しない。失敗した書き込みのpartは取り除き、異常終了で残った24時間以上前のpartも、取得中のIDを避けて整理する。

## Freesound

公開ページでは実測した`.bw-search__result`と`.bw-player`の行IDから結果を読む。保存時はそのIDの詳細ページから`data-static-file-url`のHQ MP3を取得する。LQの名前を置換してHQを捏造しない。個別ページのCreative Commons URLで版とクレジットを確定し、音声解析の返り値からrendererへ反映する。原本WAVとプレビューMP3を区別し、未知の権利を許可扱いにしない。

キー設定時の検索は公式の`/apiv2/search/`へ切り替え、必要なメタデータをfieldsでまとめて取得する。キーはAuthorizationヘッダだけへ入れ、検索URLやCDNリクエストへ入れない。401/429ではそのサイトのエラーとして扱い、公開検索へ逃がして制限を迂回しない。メタデータ取得は音声先読みで埋まらない枠を使い、試聴・保存への昇格にも対応する。

`api-keys.cjs`はセッション専用と端末保存を分ける。端末保存ではsafeStorageの非同期暗号化を使い、保護機能がない場合は平文へ落とさない。設定画面の表示可否はOS・バックエンドの対応状況だけで判断し、isEncryptionAvailableのような同期キーチェーン照会をしない。実際の暗号化・復号が必要になったときだけ非同期で保護機能を初期化する。キー復元の完了をFreesoundの検索だけが待ち、他サイトやウィンドウの作成を止めない。API検証中・暗号化中に解除されたキーを後から保存しないよう世代を確認する。

長い音源は転送の合計時間ではなく無通信時間でタイムアウトする。Freesoundは`onHeaders`/`onChunk`で音声をキャッシュの`.part`へ順に書き、全長が既知なら`growing-audio.cjs`から受信済みバイトをアプリ内プロトコルへ渡す。Readerは現在のEOFで終了せず追加入力を待つ。完了時だけ確定ファイルへrenameし、保存・ヘッダ解析は確定を待つ。波形取得の`?waveform=1`は先読みを操作優先度へ昇格させない。範囲外Range・切断・キャンセルで読み出し参照を解放し、試聴のキャンセルで共有中の保存を中断しない。全長不明時と他のプロバイダは全量待ち。公開経路の実サイト検証、公式APIの制御応答検証、暗号化保存の保護器差し替え単体検証を区別して記録する。

## Pixabay

`pixabay.cjs`は音楽と効果音の検索ページを別々のChromiumワーカーで開き、サイト自身が読み込んだ`window.__BOOTSTRAP__.page.results`を使う。行ID・種別と詳細ページURLを照合し、その行の`sources.src`だけを音源URLにする。画像や波形のURL置換はしない。2種別の結果を到着順に流し、片方の障害は他方の取得後にサイトエラーとして伝える。音声取得はブラウザ検索とは独立の優先キューで、Freesoundと同じキャッシュの逐次書き込みに接続する。

観測した原本ダウンロードの導線はゲスト向け確認フォームを返したため、自動化しない。別途公開されている試聴MP3を取得し、`isPreview:true`を維持する。Pixabay Content Licenseの商用利用・表記任意と、単体再配布・アダルト用途の禁止を正規化する。Content ID登録済みの事実を登録許可と取り違えず、前者は橙の注意、後者は未確認として扱う。参照規約は https://pixabay.com/service/terms/ 、概要は https://pixabay.com/service/license-summary/ 。

## アプリの更新

`site-module.cjs`がオンライン10サイトを生成する入口。`module-files.cjs`で配布ファイルを列挙し、`build-modules.cjs`が小さなJSONバンドルとSHA-256入りmanifestを生成する。

`module-updates.cjs`は固定したGitHub Releasesの`modules`タグから更新情報を取得する。インストール済みモジュールはuserData配下の版・ハッシュ別フォルダへ保存し、検証後にactiveポインターを更新する。起動時にCommonJSとして読み込み、外部依存はインストール済み本体から解決する。10サイトのインターフェースを確認してから使い、失敗したら同梱版に戻る。

本体の画面、音声処理、ローカルフォルダ、キャッシュとファイル操作は本体側。モジュールで更新するのはサイト取得処理とそのヘルパー・注入コード。新たなネイティブ依存やAPI変更が必要なら本体を手動で差し替える。

本体の自動差し替えとelectron-updaterは撤去した。独自URL・正式署名・Windows実機は完成の前提にしない。更新の詳細は[release.md](release.md)。

## ローカルファイルの差し替え

ローカル索引はパスに基づく素材IDを保ち、size・mtime・ctime・inodeが変わるとメタデータを再解析する。再検索でその変更をrendererへ渡し、波形・取得URLのキャッシュを破棄する。ローカル音源の再生URLは改訂情報をクエリに含めるため、同じパスの旧音声をChromiumが使い続けない。解析の完了時にも改訂情報を照合し、古い非同期処理が新しい波形や取得Promiseを上書きしない。

一括書き出しの再利用は、ローカル原本のファイル情報も照合する。未変更なら既存の書き出しを再利用し、変更後は`copyUnique`で新規保存する。既存の書き出しや原本は上書きしない。オンライン素材の保存先再利用と、ローカル原本のパスを直接コピーする動作は引き続き利用できる。

検索語・サイト選択はmainのUI状態にも保存する。起動時はこれを復元し、用途ごとのサイト設定がDOMStorageにあればそちらを優先して適用する。検索中の終了でも古い別用途のサイト選択が上書きしないよう、用途設定の復元を最後に行う。

DOVA / OpenTracksは `providers/dova.cjs` でBGM・効果音を並行検索する。検索時は一覧だけを読み、音声を要求された時に対象トラックの詳細・ダウンロードフォームを読む。CSRF cookieとトラック番号を用いた正規のPOSTが返すMP3 URLを優先し、失敗時だけHTML5試聴URLへ戻る。署名が切れたらページから再取得する。音源データの同梱・形式変換はしない。

サイト追加に伴うモジュールAPIは2。`allsample-modules-v2.json` を参照し、旧本体のAPI 1用 `allsample-modules.json` は更新しない。古い本体へ新しい構成を誤配信しないための区別で、別の更新サービスは設けない。
